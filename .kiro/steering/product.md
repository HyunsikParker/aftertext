# Aftertext

This is a community notice reader and editor that revives teletext. The primary actions are reading a numbered page, writing a notice, exporting a bulletin file, importing a shared file, and reopening the saved bulletin offline.

Keep the original notice text, punctuation, whitespace and Unicode intact. A 40-column view is a presentation of that text. Always retain the full-text reading view. Show issue dates and distinguish example, imported and saved copies. Never describe cached information as live.

No paid APIs, accounts, analytics, remote fonts or runtime models. Use native browser ES modules, a service worker, local storage and Node's built-in test runner. Input errors must preserve the existing bulletin. Render imported text through DOM text APIs.

The example is fictional. Do not invent user research, user counts, endorsements, live alerts or competition results. Keep UI labels concrete. Tests establish only the cases actually exercised.

The initial Kiro specification is preserved under specs/aftertext/kiro-spec.md. Read decisions.md for the corrections adopted before implementation. All code was started after the Kiroween 2026 submission period opened. Concept notes existed before opening and are disclosed separately.
